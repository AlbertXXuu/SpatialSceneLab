# Native observed-surface editing: S1 measured report

[中文](EDITING-S1-2026-10-06.zh-CN.md) · [Runbook](../docs/EDITING-S1.md) ·
[Download editable scene](../examples/edit-workflow/combined-study-editable.zip)

Measured on 2026-10-06, Beijing time. **Six development scene task chains passed**,
including 24 committed edit operations, 24 native undo/redo cycles and six fresh
Blender-process reopen checks. Fifteen separate native controls also passed. This
establishes an editable observed-surface workflow with reproducible checks; the
initial B0 object partitions and reconstruction holes remain in the assets.

## Inputs, task and environment

The six original MIT S0 scene groups supply **491,066 reconstructed triangle
instances**. S1 loads each fixed B0 `surface-scene.json` and its hashed PLY parts;
it does not regenerate the mesh or read independent reference labels. The B0
rule leaves candidate-boundary and unresolved faces in environment. These are
observed surface regions, rather than complete recovered objects.

Each task uses two explicit region identities from `run_edit_suite.TASKS`:

The fixed chain transfers 12 environment faces to the primary region, translates
it `(0.25, -0.1, 0)` m in Blender world Z-up, rotates the secondary 32 degrees
about world Z around its current geometry bounds center, then transfers 8 faces
to that already transformed secondary. The scripted selection chooses environment
face centroids nearest the target bounds center without reference labels. It
tests transfer and transform preservation; it does not demonstrate correct
segmentation, a beneficial ownership correction or a measured reduction in human work.

## What is checked

Every input face receives a unique integer source identity whose range maps to
its original part SHA256. Native separate/join changes ownership while the
verifier follows each source face's world corners, linear RGBA, numeric material
properties, owner and reviewed flag. Each of the four edits is followed by actual
native undo and redo with explicit background checkpoints. A new Blender process
then reopens `after.blend` and checks the saved state, source registry and journal.
The batch verifies scripted native operations; interactive timing is a separate
acceptance item.

The GLB verifier compares **oriented triangle geometry one-to-one with
multiplicity**, under a maximum corner-distance tolerance of **0.00005 m**. It
accepts vertex reordering and exporter seam splitting without collapsing nearby
vertices onto an arbitrary source index. Cyclic corner correspondence also
supports numeric per-corner color and per-face material checks. Material checks
cover roughness, metallic value, a linked Base Color input and vertex-color node
presence; they do not trace arbitrary shader graphs, compare textures or appearance
under all lighting. Welded vertex/seam identity is outside this geometric verdict.

Native `.blend` face attributes and the journal remain authoritative for editing.
GLB region extras preserve region identities and provenance. The hash-bound
`.identity.json` records lineage in **native face order**, not a GLB face identity
restoration mapping.

## Measured outcomes

The final frozen-source suite completed **6/6** chains in **117.2958371 s**,
including each edit process and fresh reopen process. Per-case task process times
above include startup, verification and, for the combined study, rendering.
All six fresh reopen processes passed. Exact source hashes, case checks and
denominators are in [edit-suite-results.json](editing-s1/edit-suite-results.json)
and the [metrics CSV](editing-s1/metrics.csv).

| Quantity | Observed maximum / count | Acceptance |
|---|---:|---|
| Native expected-vs-actual world corner error | 4.77620260 × 10⁻⁷ m | ≤ 5 × 10⁻⁵ m |
| GLB round-trip matched world corner error | 1.28392334 × 10⁻⁶ m | ≤ 5 × 10⁻⁵ m |
| GLB per-corner linear RGBA component difference | 1.78813934 × 10⁻⁷ | ≤ 1/255 + 10⁻⁶ |
| Native material-property / color preservation | All state checks passed | Numeric checks at each operation, undo/redo and reopen |
| Source inventory and committed journal | 491,066 faces; four journal records per case | IDs, owners and reviewed flags retained |
| Deliberate color and material changes | Both rejected in each of six cases | Appearance checker must fail |

The twelve bounded face transfers took **0.0416001–0.1491122 s** in this one
sequential local run. Their empirical interpolated 95th percentile is **0.12903093 s**.
This is operator timing for twelve fixed 12/8-face selections, not interactive UI
p95, arbitrary selection latency or a product performance guarantee.

Maximum sampled concurrent Blender-process-tree RSS was **1,238,065,152 bytes**
(about **1.153 GiB**), in the rendered combined study. The runner sums RSS of the
Blender parent and observed descendants every 0.1 s; values can miss shorter
peaks and can include shared pages. They are not incremental allocation,
whole-machine memory or GPU VRAM. Processes without optional psutil report no
memory measurement.

not multi-view or perceptual appearance calibration.

## Controls and retained failure evidence

[controls.json](editing-s1/controls.json) records **15/15** small-mesh native
controls in fresh Blender processes, **12.1307122 s** total. They cover empty/all
face selection, same/missing destination, multi-object Edit Mode, extra selected
Object Mode objects, non-finite transforms, changed source SHA, duplicate input
and current identities, hidden-region export, excluded/blocked collections,
sidecar write failure and pair replacement failure. Invalid inputs leave state
unchanged; object-level hidden regions are included and visibility/selection are
restored. Injected caught write/rename failures preserve the prior `.blend`, GLB
and sidecar. A hard kill between two file replacements is not an atomic two-file
transaction; the binding hash detects a mismatched pair.

The S0 before/after GLB failure records are retained unchanged. A read-only
[original recheck](editing-s1/original-recheck.json) reproduced both failures.
The [repaired recheck](editing-s1/repaired-recheck.json) passes both assets without
changing their SHA256 values, while rejecting ten injected geometry/identity faults.
The old environment failure came from nearest-source-index instability around
vertices about 1.6 micrometres apart. Each original asset has **35 matched faces**
whose winding is not geometrically distinguishable at the stated tolerance;
this ambiguity is recorded explicitly rather than claimed as topology fidelity.

## Scope and continuation

The downloadable [editable combined-study package](../examples/edit-workflow/combined-study-editable.zip)
is **8,095,918 bytes** and includes before/after native documents, final GLB +
identity record, three actual renders, the standalone sidebar, README, MIT license and file hashes. Follow
the [runbook](../docs/EDITING-S1.md) to register the standalone Blender sidebar,
review faces, edit in metres/degrees, save and reproduce the full suite.

S1 supplies engineering evidence for preservation and local edit/export use.
The 18 held-out S0 groups, independently referenced real rooms, correction quality,
human correction cost, general texture/shader fidelity and whole-machine
disconnected execution remain pending in the [full protocol](../docs/NEXT-STAGE-PROTOCOL.md).
The next meaningful experiment is improving and measuring the incomplete
ownership boundaries while retaining these preservation checks.
