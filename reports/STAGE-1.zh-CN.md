# 第一阶段：对象编辑、导出与真实重建坐标集成

2026-10-02。结论：本地工程阶段**通过，研究结论仍有明确边界**。

本次任务来自用户确认的首个空间实验：用现有电脑和已有证据，检查坐标、单位、
对象身份及编辑结果能否在场景包与 GLB 导出中保持一致。最小验收为三对象受控
场景的平移和尺寸修改、数值回读、能发现真实错误的单位/轴控制，以及一份真实
重建的相机与点坐标检查。[机器结果](stage-1-results.json)保存数值与原始哈希。

## 已执行与结果

当前电脑为 Windows 11 build 26200，Python 3.13.5、NumPy 2.1.3。
实际 GPU 清单为 RTX 4060 Laptop 8188 MiB，驱动596.49。本次没有进行 GPU
推理。当前 Python 缺少 Torch、DA3、Open3D、GTSAM、rosbags、vismatch；
PATH、标准 Program Files 定向查询及 Windows 安装登记均未找到 Blender。
没有安装依赖、下载权重或调用付费服务。

受控场景有三个自行创建的刚性长方体，已知尺寸、明确米制单位与右手 Z-up
坐标。对 block-b 输入 25cm 的 X 平移，并将尺寸从60×90×60cm改为75×90×60cm。
旋转及其他两个对象保持原值。GLB 用米和 Y-up坐标，转换只应用一次；源场景、
文件哈希、对象身份和矩阵进入导出元数据。回读直接解码二进制顶点及节点矩阵，
与源场景的实际几何比较。

各视图模型缩放值保留在元数据中。这些节点保存相机变换，不编码完整的非对称
光学投影。原图、原始NPZ、完整重建和权重留在原档案，仓库只含哈希和派生指标。
历史记录及已经退役的研究候选保持独立。

模型世界坐标与TUM真值世界坐标不同。`(X,Y,Z)→(X,-Y,-Z)`仅为明确的显示
转换，不代表已经恢复重力方向。模型预测的米制尺度按原值保留；本次没有独立
物体尺寸真值，没有自动/手动物体分割，也没有对恢复出的完整物体进行编辑。
三长方体是受控验收数据。

现有Anaconda的NumPy矩阵乘法触发Windows原生DLL异常`0xc06d007e`，
`conda run`下也复现；Matplotlib多边形绘图触发同一异常。当前小矩阵计算使用
显式`einsum`，离线证据图由已安装Pillow生成，共享运行时没有修改。

## ScaRF与下一个门槛

ScaRF本次**没有运行**。官方离线模式要求已有轨迹、图片和正确相机标定。
当前缺少其推理栈；原生Windows/8GB支持仍未知。论文笔记本为12GB RTX PRO
3000 Blackwell，其速度不能视为本机测量。官方`is_mono`支持非米制轨迹，
尺度一致也不能当作绝对物体尺寸正确。

下一阶段限定为三个独立真实场景：校准相机，建立独立测量的尺度锚和物体尺寸，
记录明确对象标签与来源，比较原始/编辑后几何和导出。先在运行栈可用时做单个
六帧离线CUDA门槛，实测显存峰值与耗时，再扩展到短序列及三场景；用覆盖率、
尺寸误差和导出完整性判断是否值得继续。
